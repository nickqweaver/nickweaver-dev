# AGENTS.md

## Repo overview

- TanStack Start (React) on Cloudflare Workers; file routes in `src/routes`.
- TypeScript + Tailwind CSS.
- Content posts in `_posts` compiled at build time by `plugins/content.ts` and served through
  server functions in `src/lib/api.ts`.

## Commands

### Install

- `npm install`

### Development

- `npm run dev` (Vite dev server on `http://localhost:3000`, server code runs in workerd).

### Build

- `npm run build`
- `npm run preview` (serve the production build in workerd).

### Deploy

- SST (`sst.config.ts`) deploys the app as a Cloudflare Worker with `sst.cloudflare.TanStackStart`;
  SST state is stored in Cloudflare R2 (`home: "cloudflare"`).
- Pushes to `main` deploy production via `.github/workflows/deploy.yml`.
- Manual: `npm run deploy` (needs `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_DEFAULT_ACCOUNT_ID`).
- Don't add a `wrangler.*` file: SST rejects it and generates the Worker config itself.
- Secrets are `sst.Secret`s linked to the site and read with `Resource.<Name>.value` from
  `sst/resource`; set them with `npx sst secret set <Name> <value> --stage <stage>`.

## Code style

### Formatting

- Prettier is the source of truth (`.prettierrc.json`).
- 2-space indentation, 100 char line width.
- No semicolons, double quotes, trailing commas.
- Use `npm run format` before finalizing changes.

### Imports

- Prefer `import type` for type-only imports.
- Group imports roughly as: React/TanStack, third-party, internal `@/`, relative, styles.
- Use path alias `@/*` for `src/*` imports.

### Components

- Components are PascalCase and exported as named functions.
- Props are typed with `interface` or `type` aliases.
- Prefer explicit return types only when needed for clarity.

### Types & data

- `tsconfig.json` has `strict: true`; avoid `any`.
- Use `type` for data shapes (e.g., `Post`) and `interface` for props.
- Favor `Readonly` for immutable props when practical.
- Keep data helpers in `src/lib` and avoid direct FS usage in components.

### Naming

- camelCase for variables and functions.
- PascalCase for React components and types.
- UPPER_SNAKE_CASE for module constants.
- Prefer descriptive names over abbreviations.

### Styling

- Tailwind CSS is primary; keep classes in `className`.
- Use `cn` from `src/lib/utils.ts` for conditional class names.
- Avoid inline styles unless required.
- Prefer semantic HTML tags (`section`, `nav`, etc.).

### Accessibility

- Provide `sr-only` text for icon-only controls.
- Always include `rel="noopener noreferrer"` with `target="_blank"`.
- Keep heading order logical (`h1` → `h2` → `h3`).

### Performance

- Prefer static or server-rendered content when possible.
- Avoid large client components unless needed for interactivity.
- Keep heavy work (markdown, images) at build time, not in the Worker or client bundle.

### Error handling

- Handle parsing errors in build-time utilities (e.g., `plugins/content.ts`).
- Prefer early returns and clear error messages over silent failures.
- Avoid throwing raw errors in React components; render fallbacks where possible.

### TanStack Start conventions

- File routes live in `src/routes` (`src/routeTree.gen.ts` is generated; don't edit it).
- Use TanStack Router `Link` for internal navigation.
- Use each route's `head()` for SEO (`src/lib/seo.ts` helpers).
- Static assets live under `public/`.
- Load data in route loaders through server functions (`src/lib/api.ts`).
- No `fs` at runtime: the Worker has no filesystem.

### Content posts

- Markdown posts live in `_posts/*.md`.
- `plugins/content.ts` reads posts via `gray-matter` at build time.
- Update `Post` type when frontmatter changes.

## File organization

- `src/routes`: file routes (pages and the `/api/contact` server route).
- `src/components`: UI and shared components.
- `src/lib`: utilities and data access.
- `src/styles/globals.css`: global Tailwind styles.
- `plugins`: build-time Vite plugins (content, Open Graph images).
- `sst.config.ts`: Cloudflare infrastructure; `sst-env.d.ts` is generated by SST.
